# CSV Data Quality Reporter — Implementation Plan

## 1. Project Goal

Build a Python command-line application that accepts a user-provided CSV file and produces a concise data-quality report.

The report should help a user quickly understand:

- dataset dimensions;
- column data types;
- missing values;
- duplicate rows;
- numeric summary statistics; and
- numeric outliers detected using the IQR method.

The project should demonstrate good software-engineering practices appropriate for IDS 706, including modular Python code, testing, containerization, documentation, and reproducible execution.

The initial version should remain intentionally small. It should not attempt to become a general-purpose data-profiling framework.

---

# 2. Functional Requirements

## 2.1 CSV Input

The program must:

- accept a CSV file path through the command line;
- verify that the file exists;
- attempt to load the CSV using `pandas`;
- provide a clear error message when the file cannot be read;
- support ordinary CSV files containing numeric, categorical/string, boolean-like, and missing values.

Example intended usage:

```bash
python main.py data/sample.csv
```

or, if a package-style entry point is used later:

```bash
python -m csv_quality_reporter data/sample.csv
```

For simplicity, I recommend using the first form unless the assignment specifically rewards package entry points.

---

## 2.2 Dataset Dimensions

The report should include:

```text
Rows: 1000
Columns: 12
```

This should come directly from:

```python
df.shape
```

No interpretation is required beyond reporting the number of rows and columns.

---

## 2.3 Column Data Types

The report should list each column and its pandas-inferred data type.

Example:

```text
Column Data Types
-----------------
customer_id     int64
age             float64
state           object
is_active       bool
```

The goal is transparency rather than automatically changing data types.

The program should not attempt aggressive type inference or automatic type conversion in the first version.

---

## 2.4 Missing-Value Analysis

For each column, calculate:

- number of missing values;
- percentage of rows that are missing.

Example:

```text
Missing Values
--------------
age          15   1.50%
income        3   0.30%
state         0   0.00%
```

Missing values should be identified using pandas:

```python
df.isna()
```

This means actual values recognized by pandas as missing, such as empty CSV fields or `NaN`, count as missing.

Strings such as:

```text
"NA"
"unknown"
"missing"
"N/A"
```

should not automatically be treated as missing unless pandas already interprets them that way.

This avoids introducing subjective data-cleaning rules.

---

## 2.5 Duplicate Rows

The report should calculate the number of duplicated rows using:

```python
df.duplicated().sum()
```

The definition should be:

> A duplicate row is a row whose values across all columns exactly match an earlier row.

Example:

```text
Duplicate Rows
--------------
Duplicate rows: 8
Duplicate percentage: 0.80%
```

The application should report duplicates but should not delete them.

---

## 2.6 Numeric Summary Statistics

For numeric columns, provide standard descriptive statistics.

Recommended statistics:

- count;
- mean;
- standard deviation;
- minimum;
- 25th percentile;
- median;
- 75th percentile;
- maximum.

Using:

```python
df.describe()
```

or:

```python
numeric_df.describe()
```

is appropriate.

The program should avoid manually reimplementing standard statistics that pandas already provides correctly.

If no numeric columns exist, the report should say something like:

```text

```

rather than failing.

# 3. Numeric Outlier Logic

## 3.1 Outlier Definition

Use the standard IQR rule.

For each numeric column:

```text
Q1 = 25th percentile
Q3 = 75th percentile
IQR = Q3 - Q1
```

Define:

```text
lower bound = Q1 - 1.5 × IQR
upper bound = Q3 + 1.5 × IQR
```

A value is an outlier when:

```text
value < lower bound
```

or:

```text
value > upper bound
```

Missing numeric values should be ignored during this calculation.

---

## 3.2 Outlier Report

For each numeric column, report:

- lower bound;
- upper bound;
- number of outliers;
- optionally percentage of non-missing observations that are outliers.

Example:

```text
Numeric Outliers — IQR Method
-----------------------------
age:
  lower bound: 3.5
  upper bound: 79.5
  outliers: 4

income:
  lower bound: -15000.0
  upper bound: 125000.0
  outliers: 17
```

The program should identify unusual observations but should not delete, cap, or otherwise modify them.

---

## 3.3 Constant Numeric Columns

If a numeric column contains the same value in every non-missing row:

```text
Q1 = Q3
IQR = 0
```

The column should normally report zero outliers because every non-missing observation equals the bounds.

This case should be explicitly covered by a unit test.

# 16. Important Edge Cases

The implementation should intentionally consider the following.

## Empty CSV

A file may contain headers but zero rows.

Example:

```text
name,age,state
```

Expected behavior:

- rows = 0;
- columns = 3;
- missing percentages should avoid division-by-zero errors;
- numeric statistics may be empty;
- duplicate count = 0.

Percentage behavior should be defined explicitly.

Recommended choice:

```text
0.00%
```

for missing and duplicate percentages when there are zero rows.

---

## Completely Empty File

A zero-byte file may cause pandas to raise:

```text
EmptyDataError
```

This should become a helpful user-facing error.

Example:

```text
Error: CSV file contains no readable data.
```

---

## No Numeric Columns

Must not fail.

Print:

```text
No numeric columns found.
```

for numeric summary and outlier sections.

---

## All-Missing Numeric Column

An apparently numeric column containing only missing values may behave differently depending on pandas inference.

If selected as numeric but contains no valid observations, the outlier function should detect the empty non-missing series and report that outlier analysis is unavailable rather than calculating invalid bounds.

---

## One Numeric Observation

Quartiles can still technically be computed.

The report should not fail.

It is acceptable to rely on pandas quantile behavior and report zero outliers.

---

## Constant Numeric Column

Must avoid treating every observation as an outlier when IQR is zero.

Expected result:

```text
Outliers: 0
```

for ordinary constant data.

---

## Very Large Outlier

Large numeric values should be handled normally by pandas.

No custom overflow handling should be necessary for ordinary datasets.

---

## Missing Values

Missing numeric values must not count as outliers.

---

## Duplicate Rows Containing Missing Values

Use pandas' standard duplicate behavior rather than inventing special rules.

Document that duplicate detection is based on pandas' row-comparison behavior.

---

## Mixed Types

A column like:

```text
1
2
three
4
```

may be loaded as object/string.

It should therefore not be included in numeric statistics.

The program should not attempt to coerce it automatically.

---

## CSV Parsing Problems

Malformed rows may cause pandas parsing errors.

A readable error is sufficient.

Automatically repairing malformed CSV files is out of scope.

# 25. Risks and Design Concerns

## Risk 1: Mixing calculations and formatting

If functions calculate statistics while simultaneously printing output, tests become harder.

Mitigation:

```text
calculate first → format later
```

---

## Risk 2: Overengineering

It would be easy to create:

- reporter classes;
- analyzer classes;
- multiple packages;
- configuration objects;
- logging frameworks;
- plugin systems.

These are unnecessary.

Mitigation:

Use several small functions in one analysis module.

---

## Risk 3: Ambiguous Missing-Value Rules

Users may assume strings such as `"unknown"` are missing.

Mitigation:

Clearly document that missing values follow pandas' standard CSV parsing and `isna()` behavior.

Do not silently add domain-specific missing markers.

---

## Risk 4: Outlier Interpretation

An IQR outlier is not necessarily a bad observation.

Mitigation:

Use wording such as:

```text
IQR outlier
```

rather than:

```text
error
```

The application identifies statistical extremes, not incorrect data.

---

## Risk 5: Mixed-Type Columns

Values that look numeric may be interpreted as strings because of one invalid entry.

Mitigation:

Report pandas-inferred types and do not perform automatic coercion.

This behavior should be documented.

---

## Risk 6: Report Formatting Tests Becoming Fragile

Testing entire multiline reports character-for-character would make small formatting changes break many tests.

Mitigation:

Unit-test structured calculations separately.

Integration tests should check for key report sections rather than exact full output.

---

## Risk 7: Docker Documentation Not Matching Reality

Docker commands frequently become stale or contain path errors.

Mitigation:

Every documented Docker command should be included in the final smoke-test procedure and manually executed before submission.

# CSV Data Quality Reporter — Implementation Plan

## 1. Project Goal

Build a beginner-friendly Python command-line application that accepts a user-provided CSV file and prints a concise data-quality report.

The project should demonstrate practical software-engineering skills without unnecessary complexity. It should be easy to explain, test, run locally, and run in Docker.

The report must include:

- dataset dimensions;
- column data types;
- missing values;
- duplicate rows;

The project should not modify the input CSV. It only analyzes and reports.

The implementation should follow these principles:

- Keep the architecture simple and beginner-friendly.

## 3.7 Numeric Outlier Detection

The program must detect numeric outliers using the IQR method.

For each numeric column:

```text

Q3 = 75th percentile
IQR = Q3 - Q1
lower bound = Q1 - 1.5 × IQR
upper bound = Q3 + 1.5 × IQR
```

A non-missing value is an outlier if:

```text
value < lower bound
```

or:

```text
value > upper bound
```

Missing values must be ignored during outlier detection.

For each numeric column, report:

- Q1;
- Q3;
- IQR;
- lower bound;
- upper bound;
- outlier count.

Example:

```text
  Q1: 27.00
  Q3: 42.00
  IQR: 15.00
  Lower bound: 4.50
  Upper bound: 64.50
  Outliers: 3
```

The program should not remove, replace, cap, or otherwise modify outliers.

The report should describe them as statistical outliers, not as errors.

## 23. Risks and Design Concerns

### 23.1 Overengineering

Risk:

The project could become harder to explain if too many modules, classes, abstractions, or frameworks are introduced.

Decision:

Use only:

```text
main.py
reporter.py
```

for core application logic.

Use plain functions.

---

### 23.2 Mixing Analysis and Printing

Risk:

If statistical functions directly print results, unit testing becomes harder.

Decision:

Analysis functions should return results.

`format_report()` should handle presentation.

`main.py` should print the final string.

---

### 23.3 Ambiguous Missing Values

Risk:

Users may expect values such as `"unknown"` to count as missing.

Decision:

Use pandas' standard parsing and `isna()` behavior.

Do not create custom domain-specific missing-value rules.

---

### 23.4 Mixed-Type Columns

Risk:

A mostly numeric column with one text value may be inferred as nonnumeric.

Decision:

Respect pandas' inferred type.

Do not automatically coerce it.

---

### 23.5 Outlier Interpretation

Risk:

Users may assume an IQR outlier is incorrect data.

Decision:

Describe values as IQR-based statistical outliers only.

Do not label them as errors.

---

### 23.6 Fragile Output Tests

Risk:

Testing the entire formatted report as one exact string can make harmless formatting changes break tests.

Decision:

Unit-test calculation results separately.

Integration tests should check important output sections and messages rather than exact full output.

---

### 23.7 Docker Documentation Drift

Risk:

Documented Docker commands may not match the final image behavior.

Decision:

Include Docker commands in the manual smoke-test procedure and execute them before submission.

---
